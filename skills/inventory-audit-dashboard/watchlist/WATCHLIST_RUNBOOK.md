# Price & Vendor Watch-list + live checks — refresh runbook (Version 25, 2026-10-03, purchase returns netted)

Run from a session that has Cure_MCP (read-only). Takes about 12 calls. Folder layout (this folder): run_live.py, pricing_engine.py, supplier_names.json at the top; price_changes/ (build_pc.py, pi_rows_with_inv.json, attachments.json); returns/ (net.py, build_returns.py, raw_returns.py, returns.json); refresh/ (live check + Excel builder). Run each script from the folder it sits in.

1. PI lines (watch-list + price changes). One query, LISTAGG-packed in buckets of 40 (add `RPAD('.',9000,'.') PAD` to force the result into a file):
   `PRODUCT_CODE|SUPPLIER_NO|TRANSACTION_NO|YYMMDD|LINE_QTY*UOM_FACTOR|PRIMARY_UNIT_COST|ORIGINAL_PINV_NO` from EXSYS.IM_PRODUCTS_TRANSACTIONS where T_TYPE='PI' AND STATUS='P' AND TRANSACTION_DATE >= 2026-01-01.
   Parse with parse_table.py (cells contain '|', so split on column bounds, not on '|'). Save as price_changes/pi_rows_with_inv.json. (pi_live_raw.json is no longer used.)
2. Attachments: EX_ATTACHMENTS (TRANSACTION_TYPE='PI') -> RELATED_DOCUMENT|IMAGE_ID|YYMMDD|IMAGE_FILE_NAME -> price_changes/attachments.json. Add new supplier names to supplier_names.json.
3. Purchase returns (new). Three small queries, then paste the results into returns/raw_returns.py (strings A, B, C, D) and run `python3 build_returns.py` (-> returns.json):
   A. returns with their purchase invoice: from EXSYS.IM_PRODUCTS_TRANSACTIONS t JOIN EXSYS.IM_PURCHASE_INVOICE_RETURN_M m ON m.RETURN_PINV_NO = t.TRANSACTION_NO where t.T_TYPE='PR' AND t.STATUS='P' -> ret_no, date, m.PINV_NO, supplier, product, LINE_QTY*UOM_FACTOR, PRIMARY_UNIT_COST, POSTED_BY, store.
   B. per return line: the receipt date, the invoiced qty of that product on that purchase invoice, and the dispensed qty between receipt and return (correlated sub-selects; keep to the return lines only).
   C. per return line: number / qty of DS and TS movements of that product between receipt and return, and how many were costed within 1% of the returned cost. Run B and C as separate queries: one combined query timed out on the server.
   D. (optional) the ERP unit cost on those later movements, for returned products that have fewer than two other purchases.
   Words to avoid in SQL: CREATE (so no CREATED_BY - use POSTED_BY), UPDATE, TRUNCATE, WITH.
4. Set AS_OF in price_changes/build_pc.py and the as_of in run_live.py; run `python3 run_live.py` (-> live_result.json: blocks and watch-list on lines NET of returns, plus the returns bridge) and `cd price_changes && python3 build_pc.py` (-> price_changes.json incl. events_returned). The 90-day window start is derived from AS_OF.
5. Live stock check: VINV_STORE_PRODUCTS where ONHAND_QTY<>0 packed as product|org|store|onhand (-> live_balances.json); last posted unit cost for products new since the snapshot (est dict in refresh/build_live_check.py); run build_live_check.py (needs _state.pkl of the snapshot) -> live_check.json.
6. Re-embed ONLY these keys into the published dashboard's audit-data JSON: watchlist, price_changes, live_check, returns_review (events_returned moves out of price_changes into returns_review), plus the purchasing blocks (purchases_by_supplier, product_supplier_price_matrix, supplier_savings_opportunities, price_outliers_flagged, vendor_concentration, kpi.price_gap_savings_identified) which are now net of returns. Templates: refresh/apply_refresh.py and returns/apply_returns.py (the latter also adds the section, CSS and Ask-AI digest entry once; on a later refresh run only its data part). Do NOT use refresh_dashboard_json.py as is: it would wipe the keys added since the 2026-09-23 build.
7. Republish to the same URL with capabilities {"downloads": {}, "sample": {}, "db": {}, "user": {"scopes": ["profile"]}}. Alert statuses live in db collection `watchlist_status`, returned-line review statuses in `returns_review`; both persist across republishes.
8. Excel: export the embedded JSON (audit_v25.json) and run `python3 refresh/build_xlsx_refresh.py <workbook> <audit.json> <out.xlsx> [scan base folder]` (27 sheets, incl. Returns & Identity Review).

Rules in force (see cfo-cure-kit-spec.md section 15): a return is matched to its invoice by PINV_NO; returned qty is removed pro rata from that invoice line before any price test (a fully returned line never counts as a price); returned lines are scored for item-identity review (price far from usual = 2 points; returned in full, stock moved before the return, later-month return, SAR 5,000+ = 1 point each; High 4+, Medium 2-3). The ERP stores no supplier item description, so a name mismatch is confirmed only on the scan.
